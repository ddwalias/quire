# Class-for-class mirroring plan

**Goal.** Give Quire the same type structure as Mathcad Prime 12. Each in-scope Mathcad type gets a Quire type with
the same name, kind, inheritance and member signatures. Only the root namespace and the app name change. Method-level
behavioral equivalence is the goal (§3c); accepted intentional departures are recorded separately and are not called
matches.

**Boundary.** MirrorGen establishes structure from assembly metadata: type and member names, signatures, base types
and interfaces, read as data. The generator itself does not load or run Mathcad methods or read their bodies. For
behavior, agents must use REA MCP to analyze the original counterpart before implementing or changing mirrored
behavior (§3c, D9): inspect managed method bodies as IL or decompiled pseudocode, and use native REA analysis for
counterparts in native DLLs where supported. User approval for this analysis is already given and does not need
renewal per method. Use the analysis as evidence, then write Quire implementations independently; do not paste
proprietary method bodies or pseudocode verbatim. Approval does not establish licensing rights: applicable license
and legal constraints for analysis and distribution still need confirming. If REA is unavailable, unreadable or
ambiguous, record the method as blocked and ask for access or clarification instead of guessing or claiming
equivalence. Any intentional structural or behavioral departure from an established Mathcad contract must be
recorded in [`deviations.md`](deviations.md) before Quire relies on it; unknown behavior and suspected bugs are not
intentional deviations.

**Status.** Phase 0 is done (§3). Phase 1 is done at type level (§3a) but reopened at method level (§3c). All 5,378
in-scope types exist as generated stubs or merged hand-written code. The engine runtime (`Mpl.Run`, `Mcd`,
`Engine.IEngine`) is implemented, the solution builds, and the 213 behaviour tests plus 31 shape tests pass. This
does not establish that all mirrored methods match Mathcad; individual method equivalence remains open until its
evidence and tests are recorded. The engine's result dictionaries match Mathcad's signatures, but their contents are
still provisional (§3b). [`type-map.csv`](type-map.csv) lists every Mathcad type with its Quire target name, its
status and its phase.

### 1.1 Why the toolchain types are excluded

When MSVC compiles native C++ into a mixed-mode .NET assembly, it has to put a metadata placeholder into the DLL for
every native type that managed code touches. The placeholder is an opaque value type with a size but no members.
These placeholders account for most of the 2,014 excluded entries; none of them are Mathcad classes:

| Kind | Count | What it is |
|---|---:|---|
| `<CppImplementationDetails>` / `<CrtImplementationDetails>` | 800 | Compiler helpers: module initialisers, vtable fix-ups, string-literal and static-array holders |
| `_`/`tag`-prefixed structs | 607 | Windows SDK, CRT and COM structs (`_GUID`, `_FILETIME`, `_variant_t`, `_bstr_t`, RTTI `_s__CatchableType`…), plus Intel MKL's `_MKL_Complex16` |
| `$_TypeDescriptor$…`, `$_s__RTTI…$` and similar | 231 | C++ runtime type information and exception-handling tables |
| `std.*` | 220 | The C++ standard library (`std::vector`, `std::basic_string`…) |
| `ATL.*`, `boost.*`, `Concurrency.*` | 104 | Microsoft ATL, Boost and the Concurrency Runtime |
| `vc.cppcli.*` | 48 | Signature modifier markers (`IsConst`, `IsChar16_t`, `ThisPointer`) used in `modopt`/`modreq` |
| MSVC-mangled names (`?Fn@Class@@…`) | 4 | Local types inside native functions |

Mirroring these would mean recreating Microsoft's compiler, STL and SDK, not Mathcad. They also have no members to
mirror, and .NET already has equivalents (`List<T>`, `string`, `Guid`). Exclusion is by name pattern; a review of
every `_`-prefixed name with lowercase letters moved the two PTC-authored ones (`_MCADGetPrototypeTag`, `_node`)
back into scope. PTC's own native classes in the global namespace (for example `SE_FPEOverflow_Exception`) were
never excluded; they map to `Quire.Native.<Assembly>`.

- **Open-source code** is excluded and its open-source package becomes a Quire dependency.

- **Code that is neither** (commercial, or platform runtime) gets an open-source substitute, or isn't needed in C#.

## 2. Mapping rules

| Mathcad | Quire | Notes |
|---|---|---|
| `Ptc.X` | `Quire.X` | e.g. `Ptc.Controls.Worksheet.WorksheetModel` → `Quire.Controls.Worksheet.WorksheetModel` |
| `Spirit.X` (the codename inside `MathcadPrime.dll`) | `Quire.X` | The app name change, e.g. `Spirit.MruFiles` → `Quire.MruFiles` |
| `Ptc.MathcadPrime.X`, `Mathcad.X`, `Mathsoft.X`, `MathcadAutomationPrivate.X` | `Quire.X`, `Quire.AutomationPrivate.X` | Also the app (or former company) name; no collisions result |
| `Mpl.Run.X`, `Mpl.X` | `Quire.Mpl.Run.X`, `Quire.Mpl.X` | |
| `Mcd.X` | `Quire.Mcd.X` | **D1 (decided).** Today's `Quire.Values` code moves here in phase 1 |
| `Engine.X` (`iengine`, `mccore12`, `mceng`) | `Quire.Engine.X` | |
| `System.Reflection.Emit.PTC.Mathcad.Mpl.X` (Mathcad's own IL assembly builder in `mplasb.dll`, 48 types) | `System.Reflection.Emit.Quire.Mpl.X` | **D8 (decided):** literal mirror, only `PTC.Mathcad` replaced |
| `Efi.X`, `Hex.X`, `mslisp.X`, `Mathcad.Automation.X`, other roots | `Quire.<root>.X` | |
| Global-namespace types in native wrappers | `Quire.Native.<Assembly>.X` | e.g. `efiio_.dll` → `Quire.Native.EfiioImpl` |
| Nested types (`A+B`) | Nested types | |
| Mathcad assembly | Quire project of the same name | Except the engine assemblies, which are consolidated (**D2**, below) |
| Names C# can't spell (Mpl operators `==.`, primes `abs'`) | Spelled out: `_eq_eq_dot`, `abs_prime` | `[MirrorOf]` keeps the original; see `Identifier.cs` |

**D2 layout, as built.** The consolidated projects follow the layers of Mathcad's own assembly graph, which keeps
them acyclic: `Quire.Mpl.Emit` (mplasb) → `Quire.Mpl` (mplrun) → `Quire.Mpl.Modules` (compiled Mpl modules:
`mpl*`, `hashtable`, `mcdrun`, `mcdstaticunitsystem*`) → `Quire.Engine.Utl` (utl-mgd, mcmisc) → `Quire.Efi`
(efi*) → `Quire.Automation.Native` (automation, automationmgd, componentsmgd) → `Quire.Engine` (iengine,
engutils-mgd) → `Quire.Mcd` (the other mcd*) → `Quire.Engine.Native` (mccore12, mcfront12, mceng, msclr, msgen,
mslisp, mspcons-mgd). `Quire.Utils` holds utilsmgd.

**Duplicates.** A type compiled into several assemblies from a shared header is defined once per Quire project when
it is internal (as Mathcad has it, one copy per DLL), and once overall when it is public, in the lowest project of the
assemblies that contain it. No separate `Quire.Efi.Common` project turned out to be needed.

**Existing Quire types with no Mathcad counterpart.** `LinearParser`, `Interpreter`, `Numerics`, `Boxes`,
`VisualNodeBuilder`, `PlotGraph` and others become `internal` implementation types under a `…Internal` namespace of
their assembly. They have to exist: Mathcad's equivalents are native or BAML code that isn't visible in metadata.

The reader was cross-checked with REA: for `Ptc.Controls.SolveBlock.dll` the method counts of all 23 named types
match REA's managed-member inventory, and for `mshex.dll` the 380 exports match exactly.

### Which members are mirrored

Every member Mathcad declares is mirrored, private ones included: fields, constructors, methods, properties and events.
Only compiler-generated members are left out, because their names come from a compiler rather than from Mathcad's
design. These are lambdas, local functions, iterator and async state machines, auto-property and event backing
fields, and the Mpl compiler's `$` gensyms. C# has no private virtual members, so private `newslot` virtual methods
are declared non-virtual.

### How stubs behave

- Methods and properties throw `NotImplementedException` naming the member.
- Nothing that frameworks call implicitly throws:
  - Constructors succeed, so objects can be created by WPF or as the base of hand-written classes. On a type with a
    hand-written part, they chain to its constructor so its initialisation runs.
  - Events are field-like, so subscribing (as WPF does to `PropertyChanged`) works.
  - `Dispose` and finalizers do nothing.
- An override of a concrete base member calls the base, so stubs don't break inherited behaviour (for example
  `OnTemplateChanged`).
- Interface members get throwing default bodies, so hand-written classes that implement a mirrored interface keep
  compiling until the member is implemented.

### Merging with hand-written code

The generator never edits hand-written files. It reads a build of the hand-written code alone
(`dotnet build -p:MirrorStubs=false`, which leaves `Generated/Mirror` out) and skips every member already declared
there. Where hand-written code differs, it wins and the difference goes into `notes.txt`. This covers a different
base class (four region controls), a different access, and overloads covered by optional parameters.

Existing code that clashed with Mathcad's design was moved or renamed, not merged:

| Change | Why |
|---|---|
| `ResultFormat` → `Quire.Controls.Core.ResultFormatOptions` | Mathcad's `ResultFormat` is a `DependencyObject`; Quire's is an options record |
| `MathNode` → `MathExpr` | Mathcad's `MathNode` is a class; Quire's linear-editor tree is records |
| `EngineResult` → `CalculationResult` | Mathcad's `EngineResult` is a struct |
| `Quire.Mpl.Run.Sexpr`/`Sym`/`Atom`/`SList` → `Quire.Mpl.Rl` | Mathcad's `Mpl.Run` types have a different design (`Atom` is abstract, `Sexpr` takes a tag) |
| Persistent data holding equation trees → `Quire.Controls.EquationControl`; `WorksheetPackage`/`WorksheetConverter` → `Quire.Controls.Worksheet` | Mathcad's `Ptc.Core` is the bottom layer; Quire's `Quire.Core` depended on the equation editor |

The four §5 "moves into mirrored types" stay for each phase; Phase 0 only made the names coexist.

### Things the metadata needed

- **Obfuscation.** `Ptc.EquationEditor` is obfuscated: 268 of its 491 types, and many internal members, have names
  such as `a` and `g+a`. They are mirrored verbatim.
  - Where C# forbids a clash that IL allows, the member or the nested type gets a `_` suffix (217 cases).
  - Overrides that the obfuscator renamed are declared under their base member's name.
  - Properties and events whose metadata rows were stripped are rebuilt from their special-name accessors.
  - Interface accessors implemented without a property become explicit properties (251 notes).
- **C++/CLI.** The wrappers only list direct interfaces, and some public types are built on internal ones. The
  planner walks interface closures, and lowers access where C# requires it (notes say where).
- **Excluded types in signatures.**
  - Members whose signatures use deferred types (COM interop, licensing), NRtfTree (pending D7) or unlisted C++
    templates are left out with a note (about 120 members).
  - Pointers to native toolchain types become `nint`.
  - The DevComponents base classes map to their Fluent.Ribbon/AvalonDock equivalents (D6).

### Regenerating

`dotnet build -p:MirrorStubs=false` → `MirrorGen emit` → `dotnet build` → `MirrorGen manifest` → `dotnet test`.

- `emit` needs the Mathcad install (`MATHCAD_DIR` overrides its path); the tests do not.
- `emit` refuses to read a build that includes the stubs, which `Directory.Build.targets` stamps.
- `manifest` refuses to drop lines from the checked-in manifest unless given `--accept-removals`, so every shape
  change is reviewed.
- Hand-written partials declare their constructors explicitly. Once the generated part declares Mathcad's
  constructors, C# no longer supplies the implicit one.

`PositionComparer.Compare` is the first stub made real: Quire's worksheet ordering moved there from
`WorksheetItemPositionComparer`, which now inherits it, as in Mathcad.

## 3a. Phase 1: engine runtime (type level done; method level open, §3c)

`Quire.Values` and the old `Quire.Mpl.Rl` S-expressions are gone. Their behaviour now lives in the mirrored `Mcd` and
`Mpl.Run` types inside `Quire.Mpl`. The interpreter sits behind Mathcad's `Engine.IEngine`/`IFactory` API. These
describe current Quire behavior, not blanket method-by-method equivalence; Phase 1's method-level review remains open
under §3c. Stubs fell
from 56,114 to 55,766. `Quire.Mpl` is now 21.1% implemented and `Quire.Engine` 13.7% (see
[`coverage.md`](coverage.md)).

### Quire behavior currently implemented (method-level equivalence not established)

| Mirrored type(s) | Behaviour |
|---|---|
| `Mcd.Dim` | Current Quire behavior interns dimensions, so two dimensions are equal only when they are the same object. Seven base exponents (length, mass, time, current, temperature, substance, luminosity) are stored as multiples of 1/2520, so roots and fractional powers stay exact; `Pwr` throws when the result isn't exact. The special markers are `identity`, `polymorphic` (null), `mcd_zero`, `string_dim`, `function_dim` and `mixed_matrix_dim`. |
| `Mcd.Type`, `Named`, `Constant`, `Product` | Dimension signatures such as `length*mass/time^2` (`1` = dimensionless). `Dim.New(Product)` interns one. |
| `Mcd.Rational` | Reduced fractions, plus a continued-fraction approximation from `double`. |
| `Mcd.Unit`, `Units`, `UnitSystem` | Units carry a signature `Type` and an SI magnitude. `UnitSystem.Simplify` returns the system's default unit for an exact dimension match, and otherwise base units with rational exponents. |
| `Mcd.DimVal`, `NumVal` (+ `num_val`), `StrVal`, `RngVal`, `MatVal` (+ `mat_val`) | `NumVal` is complex (`rp`/`ip`) with a `Dim`. `MatVal` is column-major (`m_rarr`/`m_iarr`, `Index = offset + c·anr + r`). | `Mpl.Run.FunctionUtilities`, `Function`, `Rts` | User functions and built-ins are `Function`s. `Rts.RegisterThreadForCancellationChecking`/`IsCancellationRequested` carry cancellation per thread. |
| `Engine.Factory`, `IFactoryFactory`, `IFactory`, `IEngine`, `NodeCallback`, `BooleanCallback`, `NodeStatus`, `NodeType` | Mathcad's API only: `AddAfter`/`AddBefore`/`Move*`/`Update`/`Replace`/`Remove` with priorities and client cookies, `SetAutoCalc`, `CalculateNow`, and `GetValueSync`/`GetValueBeforeAsync`/`IsBoundAt`/`GetTopNodes`/`GetDefined`. The *contents* of the returned dictionaries and the meaning of each status are not yet verified (§3b). |

### Decisions made during Phase 1

- **Results are `IDictionary`s**, because Mathcad's `GetValueSync` and its relatives are declared to return
  `IDictionary`. That matches the signature only. The keys, value types, optional entries, nesting and status
  meanings are Quire's provisional choices (`Quire.Engine.Internal.ResultKeys`), not verified Mathcad equivalents.
  Establishing the real contract is tracked as unfinished work in §3b.
- **The interpreter is still real-only.** `NumVal` has an imaginary part, but no operation produces one yet.
- **Mathcad's `NodeType` is the auto-eval flag** (`AUTO_EVAL_ON`/`OFF`). The engine's old region-kind enum is
  now the internal `NodeKind`.
- **Hand-written enums and delegates carry no `[MirrorOf]`.** The generator treats a tagged enum or delegate as
  its own output (`HandWritten.Find`). `NodeCallback`, `BooleanCallback`, `NodeStatus` and `NodeType` are therefore
  untagged, so the shape test doesn't cover them. They were checked by hand against `MirrorGen dump iengine`.
- **Stub overloads can capture calls.** A generated stub silently drops its arguments. The literal `0` in
  `new Tok(atom, 0)` binds to the `(Atom, int)` stub rather than the hand-written `(Atom, uint)` constructor.
  Overloads like that are now written by hand to forward their arguments; check for the same trap when a call
  site passes literals.
- **Edits never fail after taking effect.** With auto-calc on, a cancelled pass inside `AddAfter`/`Update`/… is
  swallowed and leaves the remaining nodes dirty. `GetValueSync` reports any node at or below the first dirty node as
  `NODE_NOT_COMPUTING`, with its previous value.
- **`Update` with an unchanged Rl sends no callback**, so the controller reposts the node's last result itself;
  otherwise a cosmetic edit would leave the region Pending.
- **The Rl reader is internal** (`Quire.Engine.Internal.RlReader`) until a later phase needs `Mpl.Run.Io`.

### Left open from the Phase 1 review

- `default(Rational)` is 0/0, because Mathcad's public `Numerator`/`Denominator` fields leave no room for a hidden
  offset. Mathcad's implicit `double → Rational` conversion is kept, and it throws for values that don't fit.
- Every `Dim.Mult`/`Div` allocates and takes the intern lock. Matrix display re-runs `UnitSystem.Simplify` for
  each element. Both are fast enough for worksheets today; cache per dimension if profiling says otherwise.
- Several generated stub constructors (`MatVal(double[])`, `MatVal(MatVal)`, `real_constant(string)`, …) would
  return empty values if hand-written code called them. None is called today. A check that fails on such calls
  would be a worthwhile shape-test addition.

### Quire-only code

These are internal and have no Mathcad counterpart:
- `Quire.Mpl.Internal.BuiltinUnits`: the unit table, the SI/USCS/CGS systems and constants.
- `Quire.Engine.Internal`:
  - `WorksheetEngine` and `EngineFactory`, which implement the API.
  - `Interpreter`, `Builtins`, `Ops`, `MatrixOps`, `Numerics` and `Env`/`UserFunction`/`BuiltinFunction`.
  - `NodeResult`/`ResultKeys`, `TraceVal` and the `Rl`/`Val` helpers.

On mirrored types, the Quire-only members are:
- On `Dim`: `Parse`, `Format`, `Coordinates`, `Denominator` and `BaseNames`.
- On `UnitSystem`: `m_defaults`.
- The convenience accessors on `MatVal` (`Rows`, `Cols`, `Row`, `Column`, `SubMatrix`) and `SCons` (`first`…`fifth`, `list1`–`list4`).

## 3b. Unfinished: engine result-dictionary compatibility

**Status: open. Scheduled at the start of Phase 2**, before any of the result-node hierarchy, `ResultManager` or the
Calculation handlers are built on top of it. Until it is done, nothing in Quire may claim that its engine results are
Mathcad-compatible.

A matching return signature (`IDictionary GetValueSync(int, int)`, `GetValueAsync`, `GetValueAfter`,
`GetValueBeforeAsync`) says nothing about what the dictionary holds. The keys, the type of each value, which entries
are optional, how aggregate results nest, and what each `NodeStatus` means are all part of the contract. A
Mathcad-shaped consumer would depend on all of them. Quire's current answers were chosen for Quire, not verified.

### What Quire produces today (provisional)

The keys are defined in `Quire.Engine.Internal.ResultKeys`. They are written by `NodeResult.ToDictionary` and
`WorksheetEngine.ValueDictionary`, and read by `Quire.Calculation.ValueToIResultNodeTransform`.

| Key | Value | Present |
|---|---|---|
| `status` | `NodeStatus` | Always |
| `value` | `DimVal` or null | Node results and scope look-ups |
| `table` | `bool` | Node results |
| `defined` | `string[]` | Node results |
| `error`, `symbol` | `string`, `string` or null | When the node failed |
| `warning` | `string` | When there is a warning |
| `display-scale`, `display-offset` | `double` | When the region has a unit override |
| `children` | `ArrayList` of nested dictionaries with the same keys | Aggregates such as solve blocks |

The statuses Quire uses are:
- `NODE_READY`: calculated.
- `NODE_INVALID`: failed, or the name is unbound in a scope look-up.
- `NODE_NOT_COMPUTING`: never calculated, or out of date, possibly with the previous value.

Quire never produces `NODE_COMPUTING` or `NODE_TREATED_READY`. The member names come from metadata; the meanings
above are Quire's assumptions.

2. **Corroborate and record evidence.** Documentation, public examples, metadata constants and black-box observations

3. **Implement independently on evidence.** Update the engine and consumers (`ValueToIResultNodeTransform`,

5. **Claim only what the evidence supports.** Docs, comments and tests should say "Mathcad-compatible" only for the

## 3c. Method-by-method fidelity

**Status: adopted 2026-10-14, not yet started.** Phases 0 and 1 matched Mathcad class by class: every type and
member signature exists. Behaviour, however, mostly lives in Quire-only internals, and most mirrored members are
still stubs. This is a method-level target, not a claim that existing methods already match. Each mirrored behavior
must be analyzed with REA MCP before implementation or change, then independently implemented and tested.

### Rules

1. **Behaviour lives in the Mathcad method that owns it.** Logic moves out of Quire-only helpers into the
   mirrored member whose name and signature say it does that job. For example:
   - arithmetic and comparisons in `Ops`/`MatrixOps` go onto `DimVal`, `NumVal` and `MatVal` members;
   - built-ins move into the `Function` hierarchy.

   Each move is confirmed per method from REA analysis and the evidence below, not assumed from names, signatures or
   in bulk. Quire-only code shrinks to what has no Mathcad counterpart, and the manifest keeps listing what remains.
2. **REA analysis is required before implementation or behavior changes.** Use REA MCP to inspect/decompile managed
   method bodies as IL or pseudocode. For a counterpart in a native DLL, use native REA analysis where supported.
   Trace relevant helpers and callers/callees needed to understand contracts such as keys/value types/status
   transitions, numeric edge cases and errors, mutation, constructors, events and lifecycle. Record the original
   assembly/version, type and member/signature, findings, confidence/limits, and test cases with observed and inferred
   behavior distinguished. Quire code is independently written; do not paste proprietary bodies or pseudocode. If REA
   cannot expose or clarify the counterpart, record it as blocked and ask for access or clarification rather than
   guessing.
3. **Tests are mandatory; differential tests are additional evidence.** Add behavior and regression tests for the
   analyzed contract. Compare with the original by differential test where feasible, but do not claim a test
   differential-verified unless it directly compared that behavior. REA analysis and tests against inferred cases
   alone do not prove full equivalence. No differential harness or tool setup is currently claimed here.
4. **No silent deviations.** An intentional departure must be entered in [`deviations.md`](deviations.md) before
   relying on it. The ledger entry must cite evidence for the original contract, independently describe Quire's
   behavior and rationale, state compatibility/user impact and duration/revisit plan, list tests, and record an
   explicit decision. Unknown Mathcad behavior is an open/blocked candidate, not an intentional deviation. A known
   bug or accidental mismatch must be tracked and fixed, not justified as a deviation unless an evidenced exception
   is explicitly decided. Never describe an accepted divergence as matching Mathcad.
5. **Private or externally unreachable does not automatically mean stub.** Analyze the body through REA where
   possible. If REA is unavailable, the body cannot be read, or behavior remains ambiguous, record the limit and
   block the member; do not guess or claim it equivalent.
6. **Per-method status and evidence are tracked.** Use distinct statuses:
   - **REA-analyzed**: original counterpart analysis is recorded; Quire behavior tests have not yet passed.
   - **REA-analyzed + behavior-tested**: independently implemented behavior/regression tests pass, but no direct
     comparison with Mathcad is claimed.
   - **documentation-only**: behavior is supported only by documentation; this is insufficient for completion and
     remains open/blocked pending required REA analysis or clarification.
   - **differential-verified**: direct comparisons with the original passed for the recorded cases only; this does
     not establish untested inputs or branches.
   - **intentional-deviation (accepted)**: an explicit `accepted-temporary` or `accepted-permanent` entry exists in
     `deviations.md`, with original-contract evidence, rationale, impact, tests and a decision record. This status is
     divergence, never equivalence.
   - **stub**, **blocked** (with reason), or **Quire-only**.

   Record status and evidence per member, including observed versus inferred behavior. MirrorGen's manifest and
   `coverage.md` currently distinguish only stubs from implemented members; they do not establish these statuses.
7. **Phase completion distinguishes equivalence from divergence.** Every mirrored member must either be independently
   implemented and behavior-tested against an evidence-backed original contract (with differential verification
   claimed only for directly compared cases), or have an accepted, tested intentional deviation recorded in
   `deviations.md`. Accepted deviations are completion exceptions only as transparently recorded divergences, never
   matches. A phase-complete label is not blanket Mathcad equivalence: describe equivalence only for behavior supported
   by recorded evidence and tests, and report accepted deviations separately. Blocked members remain unresolved and
   prevent full behavioral completion; any administrative closure with blockers must say so and must not claim
   equivalence.

### Decided (2026-10-13)

- **D1:** `Mcd` → `Quire.Mcd` (literal).

- **D8:** `System.Reflection.Emit.PTC.Mathcad.Mpl` → `System.Reflection.Emit.Quire.Mpl` (literal).
- **D9 (2026-10-14):** Before implementing or changing mirrored behavior, agents must use REA MCP to analyze the
  original counterpart (§3c): managed method bodies as IL or decompiled pseudocode, and native REA analysis for
  native-DLL counterparts where supported. Trace relevant helpers/callers/callees for the contract; record
  assembly/version, type and member/signature, findings, confidence/limits, and observed versus inferred test cases.
  Write Quire independently; do not paste proprietary code. If REA is unavailable, unreadable or ambiguous, block the
  member and ask for access/clarification rather than guessing or claiming equivalence. User approval covers this
  analysis without per-method renewal; applicable licensing/legal constraints still need confirming. REA analysis
  alone is not proof: behavior/regression tests are mandatory, with differential tests where feasible. Any intentional
  departure must be recorded in [`deviations.md`](deviations.md) before relying on it; unknowns and bugs are not
  deviations, and accepted deviations never count as Mathcad-equivalent.

### Still open (none of these block Phase 0)

- **D4: stubs in the shipping build.** Either exclude stubbed features from the UI until they're real
  (recommended), or let them surface and throw.
- **D5: Creo platform libraries (§1.4).** Mirror them as PTC code, or defer them with licensing (recommended)?
- **D6: substitutes for commercial components** (§1.2). Fluent.Ribbon + AvalonDock for DevComponents, IPOPT or
  NLopt for Knitro, MathNet.Numerics for MKL. Are these acceptable, or do you prefer others?

  run with it. Knitro has no NuGet package; it is licensed directly by Artelys.
